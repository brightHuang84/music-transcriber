# 听音识谱

把一首歌放进窗口，程序会在**你自己的电脑**上：

1. 把歌分成音轨，并且可以单独听。默认用「最高质量」：人声、鼓、贝斯、吉他、钢琴、弦乐、其他乐器。也可以改成更快的「精细」或「快速」。
2. 给人声、贝斯、其他乐器识别出音符（音高、什么时候开始、持续多久、力度），画成钢琴卷帘，并标出 C4、E4 这样的音名和唱名。
3. 给鼓识别底鼓、军鼓、踩镲，画成对齐拍子的格子。
4. 估计整首歌的速度（BPM）、拍子和小节第一拍。能判断的话，也会标出简单的大和弦 / 小和弦。
5. 导出每一轨的 MIDI、合并后的 MIDI，以及分开的音频。

歌曲不会上传到网上。窗口里会显示分析进度；分析在后台进行，窗口可以继续操作。

## Ubuntu（推荐）

适用 Ubuntu 24.04、26.04 这类桌面系统（GNOME）。不需要自己安装或挑选 Python。安装脚本会用 [uv](https://docs.astral.sh/uv/) 下载 Python 3.12，系统自带的更新版本不会被拿来跑这个程序。

在这个文件夹里打开终端，运行：

```bash
chmod +x install.sh uninstall.sh
./install.sh
```

脚本会请你输入开机密码，用来安装 ffmpeg、中文字体和窗口所需的系统库。它用 uv 下载 Python 3.12 并创建虚拟环境。这个环境里没有 pip，安装包由 `uv pip` 完成。如果上次安装中途停了（例如停在 `No module named pip`），不用删文件夹，再运行一次 `./install.sh` 就会接着装。

装完后：

1. 按 Super 键（许多键盘上标着 Windows 标志）。
2. 搜索「听音识谱」。
3. 点击图标。程序会以自己的窗口打开，不会打开浏览器，也不会留下终端窗口。

想卸掉菜单图标和虚拟环境时，运行：

```bash
./uninstall.sh
```

项目文件夹还在。不再需要这个软件时，把整个文件夹删掉即可。

有 NVIDIA 显卡，并且安装时能运行 `nvidia-smi`，会安装 CUDA 版 PyTorch，分离音轨时优先用显卡。没有显卡，或显卡版没有装上，就用 CPU，结果一样，只是更慢。窗口本身用软件绘制，这和分离音轨用不用显卡是两回事。

打不开时，把这个文件发给懂电脑的朋友：`~/.local/share/tingyin-shipu/app.log`。

## Windows 和 macOS

这两边仍然可以用浏览器打开，不是 Ubuntu 上的独立窗口。

**Windows：** 安装 [Python 3.12](https://www.python.org/downloads/)（勾选 Add python.exe to PATH）和 ffmpeg（PowerShell 里运行 `winget install Gyan.FFmpeg`），然后双击 `start.bat`。不要关掉那个黑色窗口。

**macOS：** 安装 Python 3.12 和 ffmpeg（`brew install python@3.12 ffmpeg`），然后运行 `./start.sh`。不要关掉那个终端窗口。

不要用 Python 3.13 或更新的版本。Ubuntu 用户不要运行 `start.sh`，那个脚本会提示你改用 `install.sh`。

## 怎么用

1. 把 mp3、wav、m4a 或 flac 拖进窗口，或点击「选择歌曲」。
2. 等待进度走完。分离音轨最慢。默认的「最高质量」在一台 4 核、没有独显的测试电脑上，一首 3 分钟的歌大约要 30 到 40 分钟；更老的电脑（例如没有独显的旧台式机）会更久。窗口会显示下载了多少、算到第几段、这一步大约还要多久。想快一点就改选「精细」或「快速」，一首同样的歌大约一分多钟。
3. 完成后：
   - 点「人声 / 鼓 / 贝斯 / 其他乐器」切换你正在看的乐器。
   - 上传前可以选「最高质量」「精细」或「快速」。最高质量是默认：钢琴、吉他、鼓、贝斯、弦乐更干净，鼓会再拆开记。第一次大约下载 700MB 的分轨模型、300MB 的弦乐模型，鼓组大约再 440MB。精细只多用 55MB，大约一分多钟，但钢琴和吉他容易串音，小提琴仍在「其他乐器」里。快速只分人声、鼓、贝斯和其他，模型大约 84MB。管乐、铜管和合成器仍留在「其他乐器」里。
   - 「原曲」边听整首歌边看当前乐器；「只听当前乐器」只放这一轨；「有声音的轨一起」把有声音的音轨叠回去。几乎没声音的乐器按钮会变灰。
   - 「播放」会变成「暂停」。也可以点「停止」，或按空格键播放 / 暂停。拖动进度条，或在格子上点击，可以跳到那个时间。
   - 播放时画面会跟着走，播放头一直留在看得见的地方。钢琴卷帘和鼓的格子都会跟着，横着走，格子比窗口高时也会跟着上下走。用滚轮或滚动条自己移动画面之后就不再自动跟着，点「跟随」可以恢复。
   - 钢琴卷帘上的字就是音名。左边 C4 的 4 表示八度，数字越大音越高。旁边也会标唱名。砖红色是旋律，其他颜色是和声。可以只看旋律、只看和声，或看整首歌的主旋律。贝斯单独是低音。
   - 「五线谱」和钢琴卷帘可以切换。谱上有调号、拍号、和弦名，钢琴是高低音双谱表。播放时高亮会跟着换行。点「打印五线谱」可以存成 PDF。
   - 鼓的每一行是一种鼓：底鼓、军鼓、闭镲、开镲、叮叮镲、吊镲，以及高音、中音、落地通鼓。格子按十六分音符对齐。竖线是拍，颜色更深的是小节第一拍。
4. 右侧可以下载当前音轨、旋律和和声各自的 MIDI、整首五线谱（MusicXML），或打包下载。保存时会弹出「保存文件」窗口。MusicXML 用 MuseScore 打开就是窗口里的那份谱。

没有现成歌曲时，可以点「先分析一段 4 秒示例」。那是程序生成的小旋律，用来熟悉界面，同样会走完整分析。

分析过程中不要关掉听音识谱窗口。关掉窗口，这次分析就停了。

## 结果可以怎么理解

- **C4** 是中央 C。唱名 do re mi fa sol la si 对应 C D E F G A B。
- 速度 **120 BPM** 表示一分钟大约 120 拍。
- 调性和和弦是自动估计的，只作参考。程序只标大和弦和小和弦。
- 自动识谱会有错音、漏音，八度也可能偏高或偏低。把它当成学习的起点，对照着耳朵听。

窗口里就能看五线谱。下载的 MusicXML 可以用 [MuseScore](https://musescore.org/)（免费）打开，打印窗口也可以把谱存成 PDF。音轨名称是英文：Vocals、Drums、Bass、Guitar、Piano、Strings、Other。另有 Melody（长笛音色 73）、Harmony（钢琴音色 0）和一份 lead（旋律、和声、贝斯、鼓，不把每条乐器再抄一遍）。各乐器 MIDI 的音色是通用 MIDI：人声 53（Voice Oohs）、钢琴 0、吉他 25（钢弦吉他）、贝斯 33、弦乐和其他乐器都是 48（弦乐合奏）、鼓在第 10 通道。没有单独写成小提琴 40 或大提琴 42：弦乐轨里是弓弦一起，音色用弦乐合奏。

## 它在背后做了什么

窗口是 Qt 6 画出来的。里面用 Qt WebEngine（同一套 Chromium 引擎）显示原来的界面，所以钢琴卷帘、鼓点和播放都还在，但地址栏和浏览器标签都没有。分析服务只监听本机 `127.0.0.1`，随窗口一起启动，随窗口一起退出。

- 音轨分离：默认 **最高质量** 用 [BS-RoFormer](https://arxiv.org/abs/2309.02612) 的六轨模型（鼓、贝斯、吉他、钢琴明显更干净，权重约 699MB，来自社区镜像 `enerjazzer/BS-ROFO-SW-Fixed`；训练者没有单独写许可证）。人声那一轨在合唱垫上几乎是空的，所以人声仍用 Demucs **htdemucs_6s** 补上。弦乐再用一份弓弦模型拆出来（约 303MB，`oulianov/BS-Roformer-BowedStrings-Duality` 上的 `gilliaan_bowedstrings_bs_v1`，权重许可证没有单独写明），重叠用测过的 2 倍而不是配置里建议的 6 倍。「其他乐器」是从原曲里减去人声、鼓、贝斯、吉他、钢琴和弦乐后剩下的声音。**精细**只用 htdemucs_6s（约 55MB）。**快速**用 **htdemucs**（约 84MB，四轨）。都在 CPU 上跑。把 Demucs 的重叠和随机移位加大，钢琴和吉他几乎没有变好，所以没有拿来当默认。专门的人声 RoFormer 在同一段合唱上比 htdemucs_6s 更差，所以没有换。
- 音符识别：[Spotify Basic Pitch](https://github.com/spotify/basic-pitch)（ONNX，不需要安装 TensorFlow）。
- 旋律：在已经识别出的音符上取每一拍最高的音；如果最高音一下子跳得很远，而低一点的音更顺着刚才的旋律，就留低一点的那个。贝斯不参加。人声又轻又少时，不当成整首歌的主旋律；人声清楚时，整首旋律用人声，其他乐器当成和声。没有再下载一个旋律模型。
- 五线谱：有音高的音按速度对齐到八分音符，写成 MusicXML，窗口里用 [OpenSheetMusicDisplay](https://github.com/opensheetmusicdisplay/opensheetmusicdisplay) 画出来（程序自带，不用联网）。比八分音符更短的音会并到附近的拍点上。调号来自估计的调，和弦名写在谱表上方。钢琴用大谱表。鼓谱仍按十六分音符。
- 鼓点：最高质量会先用 MDX23C 鼓组模型（约 438MB，aufr33 / jarredou 的 DrumSep，权重许可证没有正式写明）把鼓轨拆成底鼓、军鼓、通鼓、踩镲、叮叮镲、吊镲，再在每一小轨上找敲击，所以同一次的底鼓和军鼓可以一起留下。踩镲再分成闭镲或开镲，通鼓再按音高分成高、中、低。精细和快速仍用 [ADTOF](https://github.com/xavriley/ADTOF-pytorch)：五种鼓各自有阈值，不是只留最响的那一种，然后再看声音本身。鼓组模型装不上时，最高质量会退回 ADTOF。ADTOF 装不上时，会退回只标底鼓、军鼓和闭镲。

第一次用某种分轨方式时，会下载对应的模型（最高质量约 700MB，弦乐约 300MB，另加鼓组约 440MB；精细约 55MB；快速约 84MB）。窗口里的进度条会显示已经下了多少。下过一次就留在这台电脑上。

## 常见问题

**安装停在 `No module named pip`，或中途报错停了。**  
再运行一次 `./install.sh`。脚本会用 `uv pip` 继续安装，不需要自己安装 pip，也不需要删掉 `.venv`。

**应用程序菜单里找不到图标。**  
再运行一次 `./install.sh`。然后注销一次，或按 Super 再搜索「听音识谱」。

**提示找不到 ffmpeg。**  
再运行 `./install.sh`。它会用系统包管理器安装 ffmpeg。

**一直停在「分离音轨」。**  
最高质量在普通电脑上就是慢的。窗口如果还在显示「第几段」或「大约还要几分钟」，就是在算，请让窗口开着。想快一点，下次改选「精细」或「快速」。第一次失败常常是因为没联网，模型没下载下来。看 `~/.local/share/tingyin-shipu/app.log`。

**提示内存不够。**  
关掉其他占内存的软件，或把歌曲剪到 1–3 分钟再试。

**人声、钢琴或吉他那一轨是灰的。**  
变灰表示这一轨几乎没有声音。纯音乐常常没有人声。快速模式不会单独分出钢琴和吉他，它们在「其他乐器」里。精细模式的钢琴和吉他有时会串到别的轨，小提琴也在「其他乐器」里。最高质量会好很多，并单独分出弦乐。管乐、铜管和合成器目前仍在「其他乐器」。

**鼓点或和弦和我听到的不一样。**  
没有镲片的歌不会硬标出踩镲。底鼓和踩镲、军鼓和吊镲如果真的一起响，会同时标出来。军鼓和通鼓如果都很低沉，仍可能换错。很密的闭镲、爵士鼓和电子鼓也容易标错。和弦遇到七和弦、转位、很多乐器一起响时会偏。旋律相对更可信，但仍然不是人工记谱。

**窗口里出现错误提示。**  
提示是写给人看的。按提示换文件、重开窗口，或把日志文件发给懂电脑的朋友。

## 给想改代码的人

```bash
export UV_PYTHON_PREFERENCE=only-managed
uv python install 3.12
uv venv --python 3.12 .venv
# uv 创建的环境没有 pip，用 uv pip，不要用 python -m pip
uv pip install --python .venv/bin/python -r requirements-dev.txt
uv pip install --python .venv/bin/python "basic-pitch==0.4.0" --no-deps
uv pip install --python .venv/bin/python -r requirements-desktop.txt
uv pip install --python .venv/bin/python --no-deps -r requirements-quality.txt
# 按 install.sh 里的方式装好 torch / torchaudio（有 nvidia-smi 用 CUDA，否则用 CPU 轮子）
.venv/bin/python -m pytest tests
.venv/bin/python -m app.desktop
```

`tests/test_smoke.py` 会用一段 4 秒合成音乐跑通快速模式的分离、识谱、鼓点、MIDI。第一次会下载模型。`tests/test_instruments.py` 在装了 FluidSynth 和通用 MIDI 音源时，再用精细模式检查钢琴、小提琴和吉他；没装就跳过，不影响安装。

## 已知限制

- 在 Ubuntu 24.04（X11）上打开过窗口。Ubuntu 26.04 的 GNOME / Wayland 用的是同一套 Qt 窗口，但那套桌面没有在这里逐项点过。
- 窗口绘制关掉了 Chromium 的 GPU 合成，避免有些机器上窗口一片空白。分离音轨仍然会在有 NVIDIA 显卡时使用 CUDA。
- 没有提供 AppImage 或 deb 安装包。安装方式是 `./install.sh`。
- 默认假设 4/4 拍。三拍子的歌，小节线可能对不齐。
- 不识别歌词。五线谱把有音高的音对齐到八分音符，不是人工精修。比八分音符更短的音会并进去，三连音不会单独标出来。鼓谱仍是十六分音符。PDF 走系统打印窗口，不另存一个排版文件。
- 一首歌最长接受约 10 分钟，文件最大约 120MB。
- 最高质量的鼓先拆成小轨再记。在两段合成的通用 MIDI 鼓上，军鼓和通鼓比只听整条鼓轨更全；叮叮镲仍会多标几次，同一次的镲也还会漏。真实歌曲里很密的镲、爵士鼓和电子鼓还是会错。精细和快速仍用 ADTOF。同一次敲击可以有几种鼓，但不会把同一次底鼓标成底鼓加落地通鼓。
- 和弦只估计大三和弦和小三和弦。
- 最高质量的钢琴、吉他、鼓、贝斯比精细干净很多，弦乐也单独成轨，但更慢，第一次下载也大。人声仍可能漏进「其他乐器」一点点。弦乐轨是小提琴和弓弦铺底合在一起，不会再拆成小提琴和大提琴。通鼓里偏高的那一只，仍常常被记成中通鼓。管乐、铜管、合成器没有单独音轨，记在「其他乐器」上，音色也是弦乐合奏。
- 精细能单独分出钢琴和吉他，分不准时音符会串到别的轨。要快、又要钢琴轨时用它。
- 快速只有四条音轨。要最快、又不需要单独的钢琴轨时用它。
- 旋律是从音符里挑出来的一条线，不是歌手专门的模型。和弦里最高的那个音，有时会被当成旋律。安静的人声串音不会抢走整首歌的旋律。
- 分析依赖锁在 Python 3.12。安装脚本会自己下载这个版本。
